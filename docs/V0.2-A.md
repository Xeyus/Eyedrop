# V0.2-A 已纳入的需求

本版本在 v0.1 基础上加入药物约束、护理流程与预览式调度。

- 环孢素模板：每日2次、固定12小时间隔；与人工泪液前后至少15分钟。保护范围不扩展到未经确认的其他药物。
- 施图伦模板：每日3次；实际用药打卡后开始10分钟闭眼护理，前3分钟按压泪囊区，接着7分钟继续闭眼；护理期间独占，不安排其他滴眼任务。
- 人工泪液模板：次数由用户填写，5或6次均支持；不因冲突增加次数。说明书建议仅供参照，以医嘱为准。
- 普通药物可配置0–60分钟护理及其中的按压时间，保存相应动作结构。
- 排程先固定医嘱时间，再安放护理和其他任务。所有已安排任务需通过硬约束校验。
- 自动排程使用有界搜索；未找到解会保留未安排任务，显示具体冲突或搜索未找到解，不宣称已证明无解、不放宽硬约束。
- 配置、作息、手动时间变化及用药后的重新调度均先预览，确认才生效。
- 实际打卡立即保留事实，冲突实际记录附加违反规则的说明；后续冲突提醒会转为未安排，等待确认新方案。记录事实并不表示建议当时用药。
- 过期未执行的任务保留待处理，漏滴单独记录，不产生补滴任务。
- 时间轴显示计划、实际时间、保护区及护理窗，并标记延迟、漏滴和冲突。
- 原计划时间、当前计划时间、实际时间及护理动作记录分离；v0.1旧数据迁移保留原有内容。
- 护理倒计时和阶段保存到本地；同次开机内以单调时钟计时，进程重开可恢复。重启后使用已存时间戳恢复；完成状态不回退。

尚不包含：每日滴药系统闹钟、开机广播自动恢复护理服务、按星期模板、导出个人用药数据。护理前台服务和通知必须在目标手机验收。
